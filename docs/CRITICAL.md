## Resolved adapter defect recorded in v0.2.40

- **SoftAP netif teardown return value:** v0.2.39 used the `void` `esp_netif_destroy_default_wifi()` wrapper, which calls `esp_wifi_clear_default_wifi_driver_and_handlers()` but ignores its `esp_err_t` result before unconditionally destroying the netif. v0.2.40 calls the error-returning clear function directly and calls `esp_netif_destroy()` only after `ESP_OK`; a failure retains the netif and latches a cleanup fault.
