# SF2 snapshot mapping to current device source

Source reviewed from v0.2.20 source tree. This is a static mapping, not proof of a production endpoint or device runtime.

| Current source | Authoritative meaning | Proposed snapshot output | Limitation |
|---|---|---|---|
| `EV_SCAN` | Fingerprint scan result; `a` is student ID; flag bit 0 is AM/PM; status bits encode Present/Late; epoch identifies local day | Final `PRESENT` or `LATE` with source event sequence/type/status | First accepted scan semantics are applied by `DayView`; endpoint must expose the effective final outcome, not every raw event as a separate mark |
| `EV_MARK` | Manual mark; `a` is student ID; `b` is day number; status can CLEAR/Present/Late/Excused | Effective Present/Late/Excused result with MARK provenance; CLEAR stays unresolved unless device derivation produces a final state | Current event has no actor/reason identity; do not fabricate audit actor or correction reason |
| `EV_CLOSE` | Session close; `a` expected count; `b` local day; session flag; coverage flag; current 300-ID writer emits five following PAYLOAD records containing the expected-ID bitmap | Coverage row with `sessionClosed`, `coverageComplete`, `expectedCount`, `expectedStudentIds`, and exact source sequence range | The close record's bitmap is the historical expected-student snapshot. The browser contract cross-checks it with the enrollment projection; it must not infer expected status solely from today's roster. Normal log open does not prove semantic CLOSE group completeness (C25). |
| `EV_GAP` | Records interrupted/untrusted time/storage/sensor intervals | `gapAffected=true` or corresponding unresolved coverage evidence | Never convert a gap to Absent |
| `EV_NOCLASS_SET/CLEAR` | Date/session or whole-day no-class state; whole-day flag is separate | `NON_CLASS_DAY` or a session omitted from `scheduledSessions`, with explicit reason | Existing event stores no human-readable reason/destination; reason metadata must be separately stored if required |
| `EV_ROSTER` + `PAYLOAD` | SET (name), DEACTIVATE, ACTIVATE | Enrollment periods as `[startInclusive,endExclusive)` from `RosterStore::intervalAt()` and name revisions from `RosterNameHistoryReader` | Read-only projections are added in v0.2.20; display-name history is the exact full string, not parsed components. Source sequence order and effective day can diverge after a backward RTC adjustment. No sex, LRN, transfer reason/destination, or versioned reporting identity store exists |
| `EventGroupAudit` | Replays and validates current commit-group framing and selected attendance/coverage fields | Boolean source-log trust gate for a future snapshot builder | Current helper is not a complete domain-semantic or cryptographic verifier, is not wired into firmware, and consumes one of 16 `LogStore` observer slots. Unsupported event types fail closed |
| `Config` timetable | Current weekday session start/end and late threshold | Calendar/session schedule as part of one config generation | Historical schedule-effective versions are absent; C17/E2 blocks complete historical calendar claims after schedule changes |
| `DayView::statusFor()` / `status_derive.cpp` | Resolves no-class, explicit marks, scan status, expected state, started/closed and coverage into Present/Late/Excused/Absent/Unverified/NA etc. | Effective `PRESENT`, `LATE`, `EXCUSED`, `ABSENT_CONFIRMED`, `NOT_SCHEDULED`, or `UNRESOLVED` | API must use the effective derived result; absence is never a stored attendance mark |

## Verified source details

- `StatusCode`: `ST_CLEAR=0`, `ST_PRESENT=1`, `ST_LATE=2`, `ST_EXCUSED=3` (`event_codec.h`).
- Session flag bit 0: `0=AM`, `1=PM`; status occupies bits 1..2 (`makeFlags` / `flagStatus`).
- `DayView::applyEvent()` applies scan only when no prior scan exists for the student/session/day; marks overwrite `mark[id]` for that day/session. `EV_CLOSE` starts collecting its following bitmap payload records into `DayView.expected`; the derived expected state for a closed session comes from that snapshot, not a fresh live roster query.
- `derive()` checks no-class first, then mark, then scan; if not expected, `D_NA`; if not started, upcoming; if not closed, pending; after close it returns Absent only when coverage is true, otherwise Unverified.
- `RosterStore::expected()` uses `from <= day && day < to`; end is exclusive. `RA_DEACTIVATE` closes an interval at the local day number of the event. `RA_ACTIVATE` opens a new interval.
- Device IDs are 1..300 and never reused under signed P9. `RosterStore` has a fixed 512-interval capacity and now exposes read-only `intervalCount()`, `intervalAt()` and sorted `knownIdAt()` accessors. Consumers must reject `!historyComplete()`; `overflow()` and malformed replay make the projection incomplete. `RosterNameHistoryReader` streams exact `RA_SET` display-name revisions with effective day and source sequence, requires a clean `EventGroupAudit`, and detects log revision changes while reading. It does not replace a reporting identity store.

## Design consequences

1. A future endpoint should construct all effective attendance statuses from one replay/view, then attach source event provenance. Do not let the browser replay the raw event log itself.
2. `ABSENT_CONFIRMED` must reference a matching closed, complete, healthy, gap-free session, and the student ID must appear in that close record's expected bitmap. The snapshot must cite the `EV_CLOSE` sequence and all five contiguous `EV_PAYLOAD` sequences (MAX_ID=300); close-group references cannot overlap attendance event references. The ESP32 must run `EventGroupAudit::readyFor()` against the exact `OpenInfo`, verify all five payload words and bitmap popcount, and cross-check the close bitmap against enrollment history. The helper only validates current event-group shapes and selected current event fields; it is not a complete semantic or cryptographic verifier. `readyFor()` also requires the exact current `OpenInfo.generation` and compares live count/sequence, preventing stale-open reuse while allowing valid post-open appends. If any input is unknown, return `UNRESOLVED`.
3. `CLEAR` is a stored mark code, not necessarily the effective daily status. The snapshot may include it only as an unresolved source state; a correctly derived effective result should take the scan/final close path into account.
4. The roster interval semantics are half-open `[from,to)`. v0.2.20 exposes read-only intervals and sorted known IDs, and streams exact display-name revisions. It does not parse legal name components or solve non-monotonic effective dates after backward RTC changes; reporting identity and movement fields remain absent (C21/C24).
5. Current `Config` stores one timetable, not historical timetable versions. `calendarComplete=true` is not supportable for an affected historical month until C17/E2 is resolved.
6. No actor/reason is currently stored for a manual attendance correction. A report may preserve the mark but cannot claim actor-level audit fields.

7. `Event.seq` is `uint32_t`. A reporting snapshot must not accept arbitrary JavaScript-safe integers as source sequence identifiers. The browser schema limits sequence references to 1..`0xFFFFFFFF`, requires every close group to have five consecutive payload records for `MAX_ID=300`, and rejects any overlap between attendance and close-group sequence references.
